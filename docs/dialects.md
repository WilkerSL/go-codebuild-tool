# SQL dialects

Repositories use `database/sql` with SQL written for one database. The dialect is chosen with `--dialect` when the project is created (default `postgres`), stored in `codebuild.json` and reused by every later build.

| Dialect | Driver | `sql.Open` name | Example DSN |
|---|---|---|---|
| `postgres` | `github.com/jackc/pgx/v5/stdlib` | `pgx` | `postgres://app:app@localhost:5432/app?sslmode=disable` |
| `sqlserver` | `github.com/microsoft/go-mssqldb` | `sqlserver` | `sqlserver://sa:secret@localhost:1433?database=app` |
| `mysql` | `github.com/go-sql-driver/mysql` | `mysql` | `app:app@tcp(localhost:3306)/app` |
| `sqlite` | `modernc.org/sqlite` (pure Go) | `sqlite` | `app.db` |

`internal/platform/database/connect_gen.go` applies the settings each driver needs: MySQL gets `parseTime=true`, `loc=UTC` and `clientFoundRows=true`; SQLite gets `foreign_keys(1)`, `busy_timeout(5000)` and `_time_format=sqlite`.

## Differences at a glance

| | postgres | sqlserver | mysql | sqlite |
|---|---|---|---|---|
| Placeholders | `$1`, reused | `@p1`, reused | `?`, arguments repeated | `?`, arguments repeated |
| Identifier quoting | `"users"` | `[users]` | `` `users` `` | `"users"` |
| Row after insert or update | `RETURNING` | `OUTPUT INSERTED.<col>` | write and `SELECT` in one transaction | `RETURNING` |
| Pagination | `LIMIT $n OFFSET $m` | `OFFSET @p ROWS FETCH NEXT @p ROWS ONLY` | `LIMIT ? OFFSET ?` | `LIMIT ? OFFSET ?` |
| Optional filters | `($1::text IS NULL OR "email" = $1)` | `(@p1 IS NULL OR [email] = @p1)` plus `OPTION (RECOMPILE)` | ``(? IS NULL OR `email` = ?)`` | `(? IS NULL OR "email" = ?)` |
| Current time | `now()` | `SYSUTCDATETIME()` | `UTC_TIMESTAMP(6)` | `strftime('%Y-%m-%d %H:%M:%f', 'now')` |
| Integer identity | `GENERATED BY DEFAULT AS IDENTITY` | `IDENTITY(1,1)` | `AUTO_INCREMENT` | `INTEGER PRIMARY KEY AUTOINCREMENT` |
| Unique index with `softdelete` | partial index | filtered index | plain unique index | partial index |
| Nullable unique column | standard | filtered `WHERE col IS NOT NULL` | standard | standard |
| `ON DELETE restrict` | `RESTRICT` | `NO ACTION` | `RESTRICT` | `RESTRICT` |
| Transactional migrations | yes | yes | no, a failed migration is marked dirty | yes, with `foreign_keys` off during the migration |
| Migration lock | `pg_advisory_lock` | `sp_getapplock` | `GET_LOCK` | `BEGIN IMMEDIATE` |

## Column types

| Spec type | postgres | sqlserver | mysql | sqlite |
|---|---|---|---|---|
| `string` with `max=n` | `VARCHAR(n)` | `NVARCHAR(n)`, `NVARCHAR(MAX)` above 4000 | `VARCHAR(n)`, `LONGTEXT` above 4096 | `TEXT` |
| `string` without `max` | `TEXT` | `NVARCHAR(MAX)` | `LONGTEXT` | `TEXT` |
| `bool` | `BOOLEAN` | `BIT` | `BOOLEAN` | `BOOLEAN` |
| `int16` / `int32` / `int`, `int64` | `SMALLINT` / `INTEGER` / `BIGINT` | `SMALLINT` / `INT` / `BIGINT` | `SMALLINT` / `INT` / `BIGINT` | `INTEGER` |
| `float32` / `float64` | `REAL` / `DOUBLE PRECISION` | `REAL` / `FLOAT` | `FLOAT` / `DOUBLE` | `REAL` |
| `[]byte` | `BYTEA` | `VARBINARY(n)` or `VARBINARY(MAX)` | `VARBINARY(n)` or `LONGBLOB` | `BLOB` |
| `time.Time` | `TIMESTAMPTZ` | `DATETIME2(7)` holding UTC | `DATETIME(6)` holding UTC | `DATETIME` text |
| `uuid.UUID` | `UUID` | `UNIQUEIDENTIFIER` | `CHAR(36)` | `TEXT` |

Enum columns without `max=` get the smallest of 32, 64, 128 or 255 characters that fits every item, so they can be indexed everywhere.

## The same operations side by side

Insert a user (columns shortened):

```sql
-- postgres
INSERT INTO "users" ("id", "name", "created_at") VALUES ($1, $2, now())
RETURNING "id", "name", "created_at"

-- sqlserver
INSERT INTO [users] ([id], [name], [created_at])
OUTPUT INSERTED.[id], INSERTED.[name], INSERTED.[created_at]
VALUES (@p1, @p2, SYSUTCDATETIME())

-- mysql (followed by SELECT ... WHERE `id` = ? in the same transaction)
INSERT INTO `users` (`id`, `name`, `created_at`) VALUES (?, ?, UTC_TIMESTAMP(6))

-- sqlite
INSERT INTO "users" ("id", "name", "created_at") VALUES (?, ?, strftime('%Y-%m-%d %H:%M:%f', 'now'))
RETURNING "id", "name", "created_at"
```

List with a filter and pagination:

```sql
-- postgres
SELECT ... FROM "users"
WHERE "deleted_at" IS NULL AND ($1::text IS NULL OR "email" = $1)
ORDER BY "created_at" DESC, "id" DESC
LIMIT $2 OFFSET $3

-- sqlserver
SELECT ... FROM [users]
WHERE [deleted_at] IS NULL AND (@p1 IS NULL OR [email] = @p1)
ORDER BY [created_at] DESC, [id] DESC
OFFSET @p2 ROWS FETCH NEXT @p3 ROWS ONLY
OPTION (RECOMPILE)

-- mysql and sqlite pass the email argument twice
WHERE `deleted_at` IS NULL AND (? IS NULL OR `email` = ?)
LIMIT ? OFFSET ?
```

Link a many-to-many pair idempotently:

```sql
-- postgres and sqlite
INSERT INTO "user_tags" ("user_id", "tag_id") VALUES ($1, $2) ON CONFLICT DO NOTHING

-- sqlserver
INSERT INTO [user_tags] ([user_id], [tag_id])
SELECT @p1, @p2
WHERE NOT EXISTS (SELECT 1 FROM [user_tags] WHERE [user_id] = @p1 AND [tag_id] = @p2)

-- mysql
INSERT INTO `user_tags` (`user_id`, `tag_id`) VALUES (?, ?)
ON DUPLICATE KEY UPDATE `user_id` = `user_id`
```

The complete generated SQL for the example specs lives in `testdata/golden/sql/<dialect>/`.

## Constraint errors

Every dialect maps driver errors to `database.ConstraintError`, which the generated repositories turn into HTTP responses: unique violations become 409 with the field name, a missing referenced row becomes 422 on the foreign key field, and deleting a referenced row becomes 409.

| Dialect | Unique | Foreign key | How the field is found |
|---|---|---|---|
| postgres | SQLSTATE `23505` | `23503` | `PgError.ConstraintName` |
| sqlserver | errors 2601 and 2627 | error 547 | the quoted constraint name in the message, which works with localized server messages |
| mysql | error 1062 | errors 1451 and 1452 | the quoted key or constraint name in the message |
| sqlite | `SQLITE_CONSTRAINT_UNIQUE` and `_PRIMARYKEY` | `SQLITE_CONSTRAINT_FOREIGNKEY` | the column list of unique errors; foreign key errors carry no name, so the field is known only when the entity has a single reference |

## Migrations

- PostgreSQL alters columns in place (`ALTER COLUMN ... TYPE ... USING`).
- SQL Server and MySQL drop and recreate the indexes, checks and foreign keys that depend on an altered column; SQL Server also manages the named default constraints `df_<table>_<column>`.
- SQLite cannot alter columns or constraints, so codebuild rebuilds the table: create `<table>__new`, copy the common columns, drop the old table, rename, recreate the indexes. The generated migrator disables foreign keys around each migration and runs `PRAGMA foreign_key_check` before committing.
- Migration files are split into statements by the migrator; a `GO` batch separator is not supported.

## Validation per dialect

`codebuild check` rejects specs the database cannot represent:

- SQL Server and MySQL cannot index unbounded text: indexed, unique, primary key and reference strings need `max=` (at most 850 characters on SQL Server, 450 for a primary key, and 768 on MySQL).
- SQL Server rejects several cascading paths to the same table and cascading cycles (`dialect_cascade`).
- MySQL has no partial indexes, so a warning explains that soft-deleted rows still hold their unique values.

## Changing the dialect

`codebuild build --dialect sqlserver` on a PostgreSQL project fails with exit code 7 and explains the impact. With `--change-dialect`, codebuild regenerates repositories, queries and platform code for the new dialect, but existing migrations stay in the old SQL. To start the new database from a fresh baseline, delete `migrations/*.sql` and `migrations/codebuild.snapshot.json` before building.
