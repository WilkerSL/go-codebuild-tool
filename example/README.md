# Library example

A small library API generated by codebuild and then extended by hand: authors, books, tags, loans and a read-only list of languages. It runs on SQLite, so you only need Go 1.27 or later; there is no database server to install.

It was created like any new project:

```bash
codebuild build --starter --module github.com/WilkerSL/go-codebuild-tool/example --dialect sqlite
```

## How the code is organized

Each domain in `internal/` has three layers:

- **Handlers** (`handler_gen.go`, `routes_gen.go`) are generated. They decode and validate requests, call the service and write responses.
- **Services** (`service.go`) belong to you. They hold business rules and call repositories explicitly; codebuild writes the first version once and never touches it again.
- **Repositories** (`repository_gen.go`, `queries_gen.go`) are generated. They run SQL with `database/sql` and accept a transaction through `WithTx`.

You can extend a repository with your own queries in a file you own, inside the same package. `internal/books/availability.go` adds `Reserve` and `Release` this way.

## What it shows

| Feature | Where |
|---|---|
| Go 1.27 capabilities: standard library `uuid` and `encoding/json/v2` | `go.mod`, `internal/platform/httpx/json_gen.go` |
| Money as integer cents, soft delete, enum with default and list filter, unique ISBN | `specs/books.go` |
| A field managed only by business logic (`available` uses `omit=create\|update`) | `specs/books.go`, `internal/books/availability.go` |
| `has_many` and `many_to_many` routes | `specs/authors.go`, `specs/books.go`, `specs/tags.go` |
| Read-only reference data and a hand-written seed migration | `specs/languages.go`, `migrations/0002_seed_languages.up.sql` |
| A rule in a service | `internal/books/service.go` rejects a `publishedAt` in the future |
| A transaction across two repositories | `internal/loans/service.go` reserves the book and creates the loan atomically; a conditional `UPDATE` makes concurrent loans of one book impossible |
| A custom endpoint | `POST /loans/{id}/return` in `internal/loans/return.go` and `return_handler.go` |
| Manual wiring for a domain with extra routes | `manualWiring` in `codebuild.json`, wiring in `cmd/api/main.go` |
| Tests of business rules, including concurrency | `internal/loans/service_test.go` |
| Liveness, readiness and request IDs | `GET /livez`, `GET /readyz`, the `X-Request-ID` header and `request_id` in every log line |
| Container image and CI | `Dockerfile`, `.github/workflows/ci.yml` |

The hand-written SQL in `availability.go` and `return.go` targets SQLite, the dialect of this project.

## Run it

```bash
cd example
export DATABASE_URL=library.db
go run ./cmd/migrate up
go run ./cmd/api
```

On Windows PowerShell use `$env:DATABASE_URL = "library.db"` and call `curl.exe` instead of `curl`.

Or with Docker:

```bash
docker build -t library .
docker run --rm -v library-data:/data --entrypoint /app/migrate library up
docker run --rm -p 8080:8080 -v library-data:/data library
```

## Try it

```bash
curl -s localhost:8080/readyz
curl -s localhost:8080/languages
```

Create an author and copy the `id` from the response:

```bash
curl -s -X POST localhost:8080/authors -d '{"name":"Ursula K. Le Guin","email":"ursula@example.com"}'
```

Create a book for that author. The price is in cents, `genre` defaults to `fiction` and every new book is available:

```bash
curl -s -X POST localhost:8080/books -d '{
  "authorId": "<author id>",
  "languageCode": "en",
  "title": "A Wizard of Earthsea",
  "isbn": "9780547773742",
  "pages": 183,
  "priceCents": 999,
  "publishedAt": "1968-11-01T00:00:00Z"
}'
```

Tag it and list it from both sides:

```bash
curl -s -X POST localhost:8080/tags -d '{"name":"fantasy"}'
curl -s -X PUT localhost:8080/books/<book id>/tags/1
curl -s localhost:8080/tags/1/books
curl -s localhost:8080/authors/<author id>/books
curl -s 'localhost:8080/books?genre=fiction&available=true&limit=10'
```

Borrow it, try to borrow it again, then return it:

```bash
curl -s -X POST localhost:8080/loans -H 'X-Request-ID: demo-1' -d '{"bookId":"<book id>","borrower":"reader@example.com","dueAt":"2030-01-01T00:00:00Z"}'
curl -s localhost:8080/books/<book id>
curl -s -X POST localhost:8080/loans -d '{"bookId":"<book id>","borrower":"other@example.com","dueAt":"2030-01-01T00:00:00Z"}'
curl -s -X POST localhost:8080/loans/1/return
curl -s localhost:8080/books/<book id>/loans
```

| Request | Answer |
|---|---|
| a loan of a book that is already on loan | 422, `bookId` is already on loan |
| returning the same loan twice | 409, the loan was already returned |
| `PUT /loans/1` after it was returned | 422, `dueAt` cannot change after the loan was returned |
| a loan with `"dueAt":"2020-01-01T00:00:00Z"` | 422, `dueAt` must be in the future |
| a book with `"publishedAt":"2999-01-01T00:00:00Z"` | 422, `publishedAt` cannot be in the future |
| a book with `"available": false` in the body | 400, the member is not allowed |
| a second book with ISBN `9780547773742` | 409, `isbn` already exists |
| `GET /books?genre=poetry` | 400, `genre` must be one of the enum items |
| `DELETE /loans/1` while the loan is active | 204, and the book becomes available again |
| `DELETE /authors/<author id>` | 204; the author is soft deleted |

Every error is an RFC 9457 problem document, and every response carries `X-Request-ID`.

SQLite does not say which foreign key failed. A book whose `languageCode` does not exist therefore gets a 422 without a field name, while the PostgreSQL, SQL Server and MySQL dialects name `languageCode`.

## Tests

```bash
go test ./...
```

The generated repository tests and `internal/loans/service_test.go` run against temporary SQLite files, so they need no setup.

## Change the API

Edit a spec, then from the repository root:

```bash
go run ./cmd/codebuild plan --dir example
go run ./cmd/codebuild build --dir example
```

Generated files are refreshed and your files stay as they are. If the generated handlers need a service method that does not exist yet, for example after adding a relation, codebuild creates it in a new file such as `internal/books/service_list_shelf_books.go` instead of editing `service.go`. A schema change produces `migrations/0003_*.sql`.
