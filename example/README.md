# Library example

A small library API generated by codebuild: authors, books, tags, loans and a read-only list of languages. It runs on SQLite, so you only need Go 1.27 or later; there is no database server to install.

It was created exactly like a new project:

```bash
codebuild build --starter --module github.com/WilkerSL/go-codebuild-tool/example --dialect sqlite
```

and then extended by hand in the places codebuild never overwrites.

## What it shows

| Feature | Where |
|---|---|
| Go 1.27 capabilities: standard library `uuid` and `encoding/json/v2` | `go.mod`, `internal/platform/httpx/json_gen.go` |
| Soft delete, enum with default and list filter, `min`/`max`, `email`, unique ISBN | `specs/books.go`, `specs/authors.go` |
| `has_many` routes: `GET /authors/{authorId}/books`, `GET /books/{bookId}/loans` | `specs/authors.go`, `specs/books.go` |
| `many_to_many` with link and unlink routes on both sides | `specs/books.go`, `specs/tags.go` |
| Integer identity keys | `specs/tags.go`, `specs/loans.go` |
| Read-only reference data with a string primary key | `specs/languages.go` |
| A hand-written migration next to the generated ones | `migrations/0002_seed_languages.up.sql` |
| A business rule in a service | `internal/books/service.go` rejects a `publishedAt` in the future |
| A service with an extra dependency and manual wiring | `internal/loans/service.go` checks that the book exists and is available; `codebuild.json` lists `loans` in `manualWiring` and `cmd/api/main.go` wires it |

Everything else under `internal/` ending in `_gen.go` or `_gen_test.go` is generated.

## Run it

```bash
cd example
export DATABASE_URL=library.db
go run ./cmd/migrate up
go run ./cmd/api
```

On Windows PowerShell use `$env:DATABASE_URL = "library.db"` and call `curl.exe` instead of `curl`.

## Try it

In another terminal:

```bash
curl -s localhost:8080/languages
```

Create an author and copy the `id` from the response:

```bash
curl -s -X POST localhost:8080/authors -d '{"name":"Ursula K. Le Guin","email":"ursula@example.com"}'
```

Create a book for that author:

```bash
curl -s -X POST localhost:8080/books -d '{
  "authorId": "<author id>",
  "languageCode": "en",
  "title": "A Wizard of Earthsea",
  "isbn": "9780547773742",
  "pages": 183,
  "price": 9.99,
  "publishedAt": "1968-11-01T00:00:00Z"
}'
```

`genre` defaults to `fiction` and `available` to `true`. Tag the book and list it from both sides:

```bash
curl -s -X POST localhost:8080/tags -d '{"name":"fantasy"}'
curl -s -X PUT localhost:8080/books/<book id>/tags/1
curl -s localhost:8080/tags/1/books
curl -s localhost:8080/books/<book id>/tags
curl -s localhost:8080/authors/<author id>/books
curl -s 'localhost:8080/books?genre=fiction&available=true&limit=10'
```

Borrow it:

```bash
curl -s -X POST localhost:8080/loans -d '{"bookId":"<book id>","borrower":"reader@example.com","dueAt":"2030-01-01T00:00:00Z"}'
curl -s localhost:8080/books/<book id>/loans
```

Now see the rules at work. Each request answers with an RFC 9457 problem document:

| Request | Answer |
|---|---|
| a loan with `"dueAt":"2020-01-01T00:00:00Z"` | 422, `dueAt` must be in the future (loans service) |
| a book with `"publishedAt":"2999-01-01T00:00:00Z"` | 422, `publishedAt` cannot be in the future (books service) |
| a second book with ISBN `9780547773742` | 409, `isbn` already exists |
| `GET /books?genre=poetry` | 400, `genre` must be one of the enum items |
| `PUT /books/<book id>` with `"available": false`, then a new loan | 422, `bookId` is not available for loans |
| a body with an unknown member such as `"author"` | 400, the member is not allowed |
| `DELETE /authors/<author id>` | 204; the author is soft deleted and disappears from reads |

SQLite does not say which foreign key failed. A book whose `languageCode` does not exist therefore gets a 422 without a field name, while the PostgreSQL, SQL Server and MySQL dialects name `languageCode`.

## Tests

```bash
go test ./...
```

The generated repository tests run against a temporary SQLite file, so they need no setup.

## Change the API

Edit a spec, then from the repository root:

```bash
go run ./cmd/codebuild plan --dir example
go run ./cmd/codebuild build --dir example
```

The services, `cmd/api/main.go` and both existing migrations stay as they are; a schema change produces `migrations/0003_*.sql`. CI runs `codebuild plan --exit-code --dir example` to keep the committed code in sync with the specs.
